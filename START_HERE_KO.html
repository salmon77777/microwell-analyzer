먼저 압축을 푸세요. 실행 파일 네 개를 같은 GitHub 폴더에 올리고, 첫 분석은 기본 자동 탐색으로 시작합니다. 실험 이미지는 공개 저장소에 올리지 않습니다.

WellScope LAMP — 설치·사용·논문용 내보내기 안내

버전 1.0.0 · 작성 2026-09-13
Microwell fluorescence analysis

이 패키지는 기존 「Microwell 어플 만들기.docx」의 마지막 버전에서 사용하던 이미지 입력 → 격자 추정 → 녹색 형광 측정 → well 분류 기능을 다시 구성한 교체용 코드입니다. 기존 코드의 단순 오류 패치가 아니라, 격자 추정법·신호 정의·결과 표시를 변경한 버전입니다. 따라서 이전 앱의 임계값이나 양성 well 개수와 자동으로 동일한 결과가 나오지는 않습니다.

먼저 할 일은 이미지가 정상적으로 표시되고 격자가 맞는지 확인하는 것입니다. 처음부터 30% 또는 3% 같은 원하는 숫자에 맞추어 설정하지 마세요.

1. 이 앱은 무엇을 하고, 무엇을 하지 않나요?

앱이 실제로 하는 일은 다음과 같습니다.

  • 이미지를 읽고, 반복되는 밝은 점의 공간 배열로 격자를 추정합니다.
  • 격자의 각 위치에서 원래 픽셀의 형광을 측정하고 주변 배경을 뺍니다.
  • 설정한 형광 임계값을 기준으로 well을 분류합니다.
  • 양성 well 수, 측정 가능한 전체 well 수, 양성 비율을 계산합니다.
  • 실제 표준 시료의 보정표를 제공한 경우에만 보정 범위 안에서 함량을 추정합니다.
  • 원본, 표시 이미지, well별 CSV, 설정, 분석 방법, 결과 보고서를 내보냅니다.

앱이 스스로 확정할 수 없는 사항도 있습니다. FL 이미지 한 장만으로 모든 well이 제대로 충전되었는지, 어두운 well이 음성인지 미충전인지, 증폭이 특이적인지, 표준 시료의 함량이 맞는지 확인할 수 없습니다. 이 앱은 AI 모델을 호출하거나 학습 모델로 생물학적 판정을 내리는 프로그램이 아닙니다. OpenCV·NumPy·SciPy 기반의 명시적 계산 코드를 사용하며, API 키는 필요하지 않습니다.

양성 well 비율과 GMO 함량은 다른 값입니다. 예를 들어 화면의 양성 비율이 63%여도 시료의 GMO 함량이 63%라는 뜻이 아닙니다. 파일 이름이 30%.png여도 프로그램이 그 이름을 읽어 결과를 30%로 맞추지 않습니다.

2. 파일은 왜 여러 개이고, 어떤 것을 올려야 하나요?

기본 실행에 필요한 파일은 네 개입니다. 네 파일은 반드시 같은 폴더에 있어야 합니다.

파일 역할 사용자가 내용을 바꿔야 하나요?
app.py 화면, 업로드, 버튼, 설정 및 분석 흐름 처음에는 바꾸지 않습니다.
wellscope_core.py 실제 격자 추정과 수치 계산 처음에는 바꾸지 않습니다.
wellscope_report.py SVG·HTML·CSV·ZIP 결과 생성 처음에는 바꾸지 않습니다.
requirements.txt 설치할 Python 패키지와 고정 버전 제공한 내용으로 교체합니다.

화면을 일관된 밝은 테마로 사용하려면 .streamlit/config.toml도 함께 적용하세요. 기능 실행에는 없어도 되지만, 논문용 화면의 배경·글자색을 일관되게 유지하는 데 필요합니다.

나머지 파일은 보조 자료입니다.

  • README_KO.md, START_HERE_KO.html: 이 안내서입니다.
  • templates/calibration_template.csv: 데이터가 없는 보정표 양식입니다.
  • tests/: 소프트웨어 시험 코드입니다. 실험 검증 데이터가 아닙니다.
  • analyze_image.py: 선택적인 명령줄 분석 도구입니다. 웹 배포에는 필요하지 않습니다.
  • QA_REPORT_KO.md: 실제로 실시한 시험과 실시하지 못한 시험을 구분한 기록입니다.
  • .gitignore: Git으로 작업할 때 비공개 이미지나 결과 파일이 실수로 포함되는 것을 줄이는 설정입니다. 웹 브라우저 업로드까지 자동 차단하지는 않습니다.

권장 저장소 구조는 다음과 같습니다.

microwell-analyzer/
├── app.py
├── wellscope_core.py
├── wellscope_report.py
├── requirements.txt
├── .streamlit/
│   └── config.toml
├── templates/
│   └── calibration_template.csv
├── tests/
├── analyze_image.py
├── README_KO.md
├── START_HERE_KO.html
└── QA_REPORT_KO.md

ZIP 파일 자체를 GitHub에 올리는 것이 아닙니다. ZIP을 풀고, 그 안에서 app.py가 보이는 폴더를 연 다음 파일들을 올립니다. WellScope_LAMP/app.py라는 새 하위 경로에 올리면서 Streamlit의 시작 파일은 여전히 app.py로 두면, 기존 앱이 계속 실행될 수 있습니다.

3. GitHub에서 기존 앱을 교체하는 순서

3-1. 기존 코드를 백업합니다

현재 Streamlit 앱이 연결된 GitHub 저장소를 엽니다. Code 메뉴의 Download ZIP으로 백업하거나, 최소한 기존 app.py와 requirements.txt 내용을 따로 저장하세요. 기존 작업을 확인할 수 있도록 GitHub의 변경 이력도 유지합니다.

이 안내서는 저장소의 내용을 직접 변경하지 않습니다. 사용자가 파일을 올리고 Commit해야 실제 앱이 바뀝니다.

3-2. 시작 파일과 브랜치를 확인합니다

Streamlit 앱 설정에서 연결된 Repository / Branch / Main file path를 확인하세요. 기존 오류 경로에는 microwell-analyzer/app.py가 보였지만, 실제 설정은 현재 앱에서 확인해야 합니다.

기존 앱의 Main file path가 app.py라면 이번에도 저장소 첫 화면에 보이는 루트 위치의 app.py를 교체하는 것이 가장 간단합니다. 브랜치가 main이 아니라 다른 이름이면, Streamlit이 보고 있는 그 브랜치를 수정해야 합니다.

3-3. 실행 파일 네 개를 함께 올립니다

GitHub 저장소의 해당 폴더에서 Add file → Upload files를 선택합니다. app.py, wellscope_core.py, wellscope_report.py, requirements.txt를 한 번에 올리세요. 업로드 목록의 파일 이름과 경로를 확인합니다.

기존 파일 교체가 확인되지 않으면 기존 app.py를 열고 연필 모양의 편집 버튼을 눌러 새 파일의 내용 전체로 교체해도 됩니다. 이 경우에도 두 보조 .py 파일과 requirements.txt를 반드시 함께 추가·교체해야 합니다.

Commit message에는 예를 들어 Replace legacy app with WellScope LAMP v1.0.0이라고 적고 Commit changes를 누릅니다. 저장소의 보호 규칙에 따라 새 브랜치와 Pull request가 필요할 수 있습니다. 그 경우에는 병합이 완료되어야 운영 브랜치의 앱에 반영됩니다.

3-4. 밝은 화면 테마를 적용합니다

압축 안의 .streamlit 폴더를 그대로 올리거나, GitHub에서 .streamlit/config.toml 경로로 파일을 만들고 제공된 config.toml 내용을 붙여 넣습니다.

확인할 경로는 config.toml이 아니라 .streamlit/config.toml입니다. Windows에서 확장자가 숨겨져 config.toml.txt가 되지 않았는지도 확인하세요.

3-5. Streamlit이 다시 설치·실행할 때까지 기다립니다

requirements.txt가 바뀌면 Community Cloud가 의존 패키지를 다시 설치합니다. 기존 URL과 app.py 경로를 유지한 교체라면 앱을 새로 만들 필요는 없습니다. 설치 중 화면이나 로그가 잠깐 바뀌는 것은 정상입니다.

화면이 예전 상태라면 새로고침한 뒤 Manage app → 로그 메뉴 → Reboot app을 사용할 수 있습니다. 오류가 나면 마지막 빨간 메시지 한 줄만 보지 말고, 설치 로그의 원인 부분을 확인하세요.

3-6. Python 버전은 우선 기존 3.13을 유지합니다

사용자가 제시한 오류 경로는 Python 3.13 환경입니다. 이번 계산 코드도 Python 3.13.5에서 시험했습니다. 우선 기존 3.13 환경에서 제공한 패키지 고정 버전을 적용하세요.

새 앱을 따로 배포한다면 Advanced settings에서 Python 3.13을 선택합니다. Community Cloud에서는 Python 자체의 버전을 바꾸기 위해 앱 재배포가 필요할 수 있지만, 이번 교체의 첫 단계에서 기존 앱을 삭제할 필요는 없습니다.

3-7. 다른 의존성 파일이 우선 적용되지 않는지 확인합니다

저장소에 uv.lock, Pipfile, environment.yml 같은 다른 환경 설정 파일이 있으면 Streamlit이 requirements.txt보다 먼저 사용할 수 있습니다. 무조건 삭제하지 말고 백업 후 어떤 방식으로 배포하는 저장소인지 확인하세요. 이 패키지는 requirements.txt 방식을 기준으로 구성했습니다.

비밀번호, GitHub 토큰, API 키, 실험 원본 이미지, 실제 결과 ZIP은 공개 저장소에 올리지 마세요. 이 앱은 API 키 없이 동작합니다.

4. 처음 실행할 때: 설정을 만지지 않고 시작하기

단계 A — 화면을 확인합니다

새 화면의 제목은 WellScope LAMP, 부제는 Microwell fluorescence analysis입니다. 왼쪽에는 이미지 입력, 분석 방식, 고급 설정 열기, 분석 실행 버튼이 있습니다. 예전처럼 여러 원형도·최소 면적·최소 거리 슬라이더를 처음부터 맞추는 구조가 아닙니다.

파일을 아직 올리지 않은 상태에서는 합성 예제로 사용법 확인을 선택해 버튼 동작을 살펴볼 수 있습니다. 합성 예제에는 항상 합성 데이터 표시가 붙고, GMO 함량 추정은 비활성화됩니다.

단계 B — 원래 이미지를 올립니다

PNG 또는 단일 페이지 8/16-bit TIFF를 권장합니다. 여러 장이 들어 있는 TIFF, 실수형 TIFF는 이 버전이 임의로 첫 페이지나 8-bit로 바꾸지 않고 중단합니다. 해당 이미지에서 사용할 한 평면을 원래 강도를 유지한 채 따로 내보내세요.

작은 화면 캡처를 키워서 올리는 것보다 원래 장비에서 내보낸 해상도의 파일이 적절합니다. 확대는 잃어버린 정보를 되돌리지 못합니다.

단계 C — 자동 탐색을 실행합니다

처음에는 자동 제안 · 탐색용을 유지하고 분석 실행을 누릅니다. 자동으로 격자 간격·방향·완만한 왜곡을 추정하고, 원래 픽셀에서 신호를 측정합니다.

자동 분석 결과에서 가장 먼저 볼 값은 GMO 함량이 아니라 격자가 well의 중심을 제대로 따라가는지입니다. 이 단계의 임계값은 밝기 분포를 나누는 Otsu 제안값입니다. 밝은 well만 있는 사진에서도 분포를 둘로 나눌 수 있으므로, 이를 검증된 생물학적 양성·음성 구분으로 해석하지 마세요.

단계 D — 격자 탭과 확대 영역을 확인합니다

격자 확인 탭에서 전체 격자를 보고, 접힌 원래 픽셀의 확대 영역 확인을 열어 가운데와 가장자리 영역을 각각 확인합니다. 청록색 +는 측정 가능한 위치, 회색 사각형은 제외된 위치입니다.

원래 파일의 가장자리에 걸린 well은 중앙이 보이더라도 주변 배경 측정 영역이 잘릴 수 있습니다. 이 경우 제외되며, 음성 well로 세지 않습니다. 따라서 행 × 열과 측정 가능 well 수가 다를 수 있습니다.

기준점이 이웃 well로 건너뛰거나, 한 well에 두 점이 생기거나, 격자가 반 칸씩 밀리면 숫자를 그대로 논문에 사용하지 마세요. 먼저 ROI·원본 해상도·알려진 배열 구조를 확인합니다.

단계 E — 결과를 저장합니다

내보내기 영역에서 전체 결과 ZIP 준비를 누른 뒤 나타나는 다운로드 버튼으로 저장합니다. 이 ZIP은 결과용 파일이므로 GitHub에 업로드하지 않습니다.

입력 이미지나 측정 설정을 바꾸면 이전 결과는 화면에서 숨겨지고 다시 실행하라는 안내가 나옵니다. 오래된 결과를 새 설정의 결과로 오인하는 것을 방지하기 위한 처리입니다.

5. 논문용 분석에서 중요한 ‘두 종류의 저장 파일’

analysis_profile.json: 측정법과 임계값을 고정하는 파일

이 파일에는 신호 채널, 원래 영상 크기/bit depth, 신호 측정 반지름, 배경 측정 범위, 형광 임계값, 프로토콜 ID가 들어 있습니다. 새로운 시료에서도 같은 정의로 측정하기 위한 파일입니다.

추천 순서는 다음과 같습니다.

  1. 음성 대조군과 양성 대조군, 대표 표준 시료에서 신호 분포를 확인합니다.
  2. 대조군과 독립 검증에 근거해 형광 임계값을 정합니다. 자동 제안값을 그대로 확정하는 절차는 아닙니다.
  3. 고정 임계값 방식으로 실행하고 결과를 확인합니다.
  4. 신호 분석 프로필 JSON을 저장합니다.
  5. 이후 표준·미지 시료에서는 저장된 분석 프로필을 선택하고 그 파일을 불러옵니다.

현재 자동 탐색에서 제안한 값도 프로필로 저장할 수 있지만, 저장했다고 대조군 검증이 완료된 것은 아닙니다. 불러오기 후 고정값으로 적용되므로 사용 전 반드시 대조군으로 확인해야 합니다.

프로필은 원래 영상 크기, bit depth, 컬러 모드가 다르면 조용히 변환해 적용하지 않습니다. 원래 영상과 촬영 조건을 일관되게 관리하세요. 프로필 ID가 같더라도 노출·DNA 양·반응 시간까지 자동으로 보증되지는 않습니다.

grid_template.json: 특정 촬영 좌표의 격자 위치를 저장하는 파일

이 파일은 well이 어디에 있는지를 저장합니다. 밝은 well이 적은 저농도 또는 음성 시료에서는 FL 이미지 자체만으로 전체 격자를 찾지 못할 수 있습니다. 이때 동일한 촬영 위치의 확인된 격자 템플릿을 사용할 수 있습니다.

단, 영상 크기만 같다고 위치가 맞는 것은 아닙니다. 촬영 위치·배율·회전·잘라낸 영역이 같고 픽셀 좌표가 정합되어 있어야 합니다. 이 버전에는 서로 다른 이미지의 자동 정합 기능이 없습니다.

고급 설정 → 격자·분석 영역 → 정합된 격자 템플릿에서 템플릿을 올리고 정합을 확인합니다. 다른 칩 사진의 템플릿을 확인 없이 그대로 적용하지 마세요.

고급 설정의 수동 격자는 언제 사용하나요?

자동 추정이 안 되지만 배열의 실제 행·열 수를 알고 있을 때 사용합니다. 네 귀퉁이 well 중심의 좌표와 행·열 수를 입력합니다. 칩 바깥 모서리 좌표가 아닙니다. 수동 격자도 결과 overlay를 검토해야 합니다.

6. 바뀐 신호 정의와 기존 임계값의 차이

이번 버전의 기본 신호는 다음과 같습니다.

Corrected signal
= well 중심 원형 영역의 원래 픽셀 평균
- 그 주위 고리 영역의 원래 픽셀 중앙값

기본 반지름은 추정 pitch의 0.22배이며, 배경 고리 범위는 0.34–0.46배입니다. 작은 이미지에도 무조건 반지름 2픽셀 이상을 강제하지 않습니다. 신호 영역과 이웃 well/배경 영역이 겹치지 않도록 비율을 제한합니다.

격자를 찾을 때만 완만한 smoothing을 사용합니다. 최종 신호는 smoothing이나 이미지 확대를 적용한 배열에서 측정하지 않습니다. 16-bit 파일은 분석에서 16-bit 원래 단위를 유지하고, 표시용 이미지만 0–65535를 0–255에 대응시킵니다.

예전 코드의 G값 150은 이번 배경 보정 신호의 150과 동일한 정의가 아닙니다. 기존 cutoff를 그대로 옮긴 후 일치하지 않는 결과를 오류로 판단하지 마세요. 먼저 새 정의로 표준·대조군을 다시 평가해야 합니다.

기본 설정은 일반적인 시작점이며, 모든 현미경·well 크기·광학 형태에 대한 최적값으로 검증된 것은 아닙니다. 특히 링 모양 신호, 매우 낮은 해상도, 불규칙 배열, 심한 왜곡, 낮은 밝기에서는 알려진 구조/템플릿이나 별도 방법 검증이 필요합니다.

7. 실제 GMO 함량과 3% 기준을 적용하는 순서

7-1. 무엇의 ‘%’인지 먼저 정합니다

이 버전은 세 가지 단위 근거를 구분합니다.

코드 뜻
calibrant_equivalent 사용한 표준 시료에 대응하는 추정 함량
gm_mass_fraction GM 질량분율로 조제·확인한 표준에 근거한 값
target_reference_copy_ratio 타깃/참조 유전자의 copy 비율로 정의한 값

타깃/참조 copy 비율 실험을 했다고 해서 자동으로 실제 식품의 GM 질량분율이 되는 것은 아닙니다. 단위 근거와 DNA 투입량·희석·매트릭스가 같다는 실험적 근거가 필요합니다. 기본 단위는 가장 보수적인 calibrant_equivalent입니다.

7-2. 형광 임계값을 고정한 뒤 표준들을 분석합니다

알고 있는 함량의 여러 표준 시료를 같은 신호 분석 프로필로 분석합니다. 표준마다 임계값을 다시 자동으로 바꾸면 서로 다른 기준의 양성 비율을 비교하게 됩니다.

앱의 보정 영역에서 현재 시료가 표준일 때: 알고 있는 함량 (%)에 실제 표준값을 입력하고 현재 결과를 표준 1행 CSV로 저장을 사용합니다. 각 표준의 행을 모아 하나의 CSV로 합칩니다. 이 기능은 고정 임계값 분석에서만 사용할 수 있습니다.

CSV 헤더는 다음과 같습니다.

sample_id,positive_fraction_pct,known_content_pct,profile_id,quantity_basis

각 열의 의미는 다음과 같습니다.

  • sample_id: 표준의 식별자.
  • positive_fraction_pct: 앱에서 계산한 양성 well 비율. 20%면 20으로 기록하고 0.2로 쓰지 않습니다.
  • known_content_pct: 표준 시료의 실제로 알고 있는 함량. 3%면 3입니다.
  • profile_id: 해당 분석에서 저장된 프로필 식별자. 앱이 자동으로 기록합니다.
  • quantity_basis: 위 표의 단위 코드. 행마다 같은 근거를 사용해야 합니다.

빈 양식에는 임의 실험값이 들어 있지 않습니다. 보정표를 만들기 위해 미지 시료에 추정값을 정답처럼 채우지 마세요.

7-3. 보정표의 지원 범위를 이해합니다

이 버전은 함량별 평균 양성 비율을 구하고, 그 평균이 함량에 따라 엄격하게 증가할 때만 구간별 선형 보간을 적용합니다. 최소 세 개의 서로 다른 함량 수준이 필요하고, 분류 기준의 아래와 위를 포함해야 합니다. 이는 코드의 최소 입력 조건이며, 적절한 실험 설계나 충분한 통계 검증의 기준을 대신하지 않습니다.

100% well이 모두 켜져 농도 차이를 구분하지 못하거나, 표준곡선이 감소/역전하는 경우 보정 적용을 중단합니다. 보정 범위를 벗어난 시료도 외삽하지 않고 Outside calibration range로 표시합니다.

회귀식, R², 검증 정확도, 신뢰구간은 임의로 생성하지 않습니다. 현재 제공된 보정 방식이 사용자의 실험에서 검증한 모델과 다르면 그대로 교체 적용해서는 안 됩니다. 예를 들어 검증된 모델이 target/reference 보정이나 비선형 식을 필요로 한다면 해당 모델에 맞는 추가 구현과 검증이 필요합니다.

7-4. 3%는 ‘연구상 분류 기준’으로 표시합니다

기본 설정은 3.0%이고, 사용자가 바꿀 수 있습니다. 이 앱은 이를 법적 표시 의무의 확정 기준이라고 주장하지 않습니다.

결과 표시 의미
Not calibrated / Not evaluated 보정 데이터가 없어 함량을 추정하지 않음
Below study threshold 검증된 보정 근거에 따른 추정값이 연구상 기준 미만
At/above study threshold 추정값이 연구상 기준 이상
Review near study threshold 기준 근처의 운영상 재검토 구간
Outside calibration range 보정 범위 밖이라 추정하지 않음

기준 미만을 non-GMO 또는 GMO 불검출이라고 바꿔 쓰지 않습니다. 2%로 추정된 시료는 3%보다 작지만, 이것만으로 GMO가 전혀 없다는 뜻은 아닙니다.

기본 재검토 폭 ±0.3%p는 사용자가 수정할 수 있는 운영상 예시값입니다. 통계적 95% 신뢰구간이나 규제상 허용오차가 아닙니다. 폭을 0으로 하면 정확한 숫자 비교만 적용되며, 3.0%는 >= 규칙에 따라 기준 이상에 포함됩니다. 연구 전에 규칙을 정하고 검증용 미지 시료에는 사후 변경하지 마세요.

7-5. Poisson 보정은 자동 적용하지 않습니다

이번 코드만으로 원래 분자의 무작위 분할, 분할 부피, 분할 후 독립 증폭 등의 조건을 확인할 수 없으므로, 양성 비율에 자동으로 Poisson 식을 적용하거나 원래 copy 수를 표시하지 않습니다. 이 버전의 함량 모듈은 사용자가 제공하는 경험적 보정표 방식입니다. 실제 digital LAMP 원리가 성립하는 실험이라면 그 조건을 확인한 다음 별도 정량 모델로 구현·검증해야 합니다.

APP_NAME = "WellScope LAMP"

11. 로컬 실행이 필요할 때만 사용하는 명령

GitHub와 Streamlit Cloud를 이용하면 아래 명령을 직접 실행할 필요는 없습니다. 개인 PC에서 독립 실행하거나 개발 시험을 할 때의 선택 경로입니다.

python -m venv .venv

Windows PowerShell에서 가상환경을 활성화한 후 설치합니다. 실행 정책 때문에 활성화가 막히면 .venv\Scripts\python을 직접 사용해도 됩니다.

.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m streamlit run app.py

테스트 코드 실행:

python -m pip install pytest
python -m pytest tests -q

UI 없이 이미지 하나를 탐색용으로 분석:

python analyze_image.py "image.png" --sample-id MW-001 --output-dir output

--threshold를 사용하면 고정 임계값이 적용됩니다. 숫자는 임의 예시가 아니라 실제 대조군에서 확인한 값을 넣어야 합니다. CLI는 함량 보정을 자동 적용하지 않으며, 이 버전의 함량 CSV 적용은 웹 UI에서 수행합니다.

12. 시험 범위와 배포 전 확인

분석 엔진과 내보내기 코드는 Python 3.13.5에서 시험했습니다. 정상 이미지 처리, 빈 입력, 16-bit 보존, 투명 픽셀 제외, 빈 이미지 중단, 수동 격자, 격자 템플릿 재사용, 수동 제외 사유, 프로필 일치, 보정표 오류, 외삽 방지, HTML 입력 이스케이프, CSV 안전 처리 등의 자동 시험을 수행했습니다.

이 제작 환경에서는 Streamlit 패키지 설치를 위한 네트워크 접근이 되지 않아 실제 Streamlit 실행/브라우저 상호작용 시험은 수행하지 못했습니다. 해당 시험 코드는 포함했지만 여기서는 skip 처리되었습니다. 독립 HTML/SVG 보고서의 Chromium 렌더링은 별도로 확인했습니다. HTML 보고서 화면을 배포 완료된 Streamlit 앱 캡처라고 표현하지 않습니다.

배포 후에는 합성 예제에서 업로드·분석 실행·탭 이동·프로필 저장·ZIP 저장을 확인하고, 실제 이미지에서 격자를 검토하세요. 계산이 실행되는 것과 계수/정량이 정확하다는 것을 구분해야 합니다. 참조 계수와 독립 시료 검증을 통과하기 전에는 최종 논문 성능 수치로 사용하지 마세요.
